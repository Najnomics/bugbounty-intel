## Description (verbatim)

### Summary

Lighthouse beacon node has a slasher feature that identifies slashable behaviours such as double vote. The slasher processes an attestation before its signature is verified. An attacker can send a crafted attestation with a large `validator_index` to cause an out-of-memory (OOM) error on a Lighthouse beacon node that is running a slasher. 

### Impact
A crafted attestation can OOM a Lighthouse beacon node running a slasher.

Slasher is off by default. The attack does not affect a Lighthouse beacon node that is not running a slasher (without using the flag `--slasher`).

### Patches
The fix stops the slasher from processing attestations before their signatures are verified. You may refer to this PR for the details: https://github.com/sigp/lighthouse/pull/9141.
