# 2026-11-25 check-specs — system-limit exhaustion → fail-open state (Drupal pre-auth RCE), unauthenticated postMessage widget XSS, deprecated lending market still wired to shared pool

Compiled 25 Nov 2026 (Africa/Lagos) from the daily sweep. Each spec: **signal → steps → automation → source (local verbatim file)**. Test only in-scope assets under the program's rules.

## 1. Availability errors that a catch block turns into trusted state ("limit exhaustion" class)
- **Signal:** code that wraps a resource/DB/file check in `try/catch` and falls back to a permissive default: installers ("already installed?" probes: `install.php`, first-admin setup routes in Drupal/WordPress/Strapi), config loaders (`catch OSError: config = {"requires_auth": False}`), feature-flag/permission loaders.
- **Limits to hit:** `EMFILE` (RLIMIT_NOFILE; systemd soft 1024) when the app leaks fds across requests (long-lived workers, e.g. uvicorn module-level dict of open files); DB `max_connections` (`SQLSTATE[HY000] [1040] Too many connections`; PostgreSQL default 100 < Apache workers = easiest; MySQL default 151 needs endpoints opening 2 connections/request); Linux ephemeral-port exhaustion via TIME_WAIT (28,232 ports / 60 s ≈ 471 new PHP→DB connections/s, error `[2002] Cannot assign requested address`) for PHP-FPM (5 default workers). `tcp_max_tw_buckets` (8,192 on the tested t3.small) can block the TIME_WAIT variant; ≥4 vCPU targets are realistic remotely.
- **Drupal chain (SA-CORE-2026-017, affects 8.9/9/10/11, not 7):** installer sequence FAIL (verify DB), FAIL (`tableExists` exception swallowed so `$existing_install=FALSE`), SUCCESS (third connection) → fresh install on a live site; choose SQLite and a DB path inside the webroot; PHP code stored in the SQLite file executes. Listed in CISA KEV as CVE-2026-132165 on 2026-11-24.
- **Automation:** (1) fingerprint installer/probe endpoints (`/core/install.php`, `/wp-admin/install.php`) returning "already installed" vs "start installation"; (2) HTTP/2 multiplexed flooder against the cheapest DB-touching endpoint (`/core/authorize.php`) while polling the probe; (3) code review rule: `catch (Exception) { $x = default }` where default weakens security; (4) check systemd/Docker limits for feasibility before spending requests.
- **Source:** [writeups/kevin_mizu/slcyber-fail2install-system-limits-drupal-preauth-rce.md](../../writeups/kevin_mizu/slcyber-fail2install-system-limits-drupal-preauth-rce.md), [posts/SLCyberSec/2026-11-24-2125265690831540630.md](../../posts/SLCyberSec/2026-11-24-2125265690831540630.md), [posts/kevin_mizu/2026-11-24-2125231431886479623.md](../../posts/kevin_mizu/2026-11-24-2125231431886479623.md).

## 2. Embedded chat/support widget: postMessage listener without origin check → stored XSS → session token mint ($2,000 + $150 retest)
- **Signal:** third-party widget iframe whose parent page talks via `postMessage`; widget page has a load-time allowlist (frame-ancestors / referrer check) but handlers are registered with `window.addEventListener('message', …)`.
- **Steps:** attacker page `document.querySelector('iframe')` → `contentWindow.postMessage({cmd:'start-chat', message:'<img src=x onerror=…>'}, '*')`; payload is stored, decoded and written unescaped inside the dialog → script runs on the widget origin; exfiltrate the session cookie to the attacker page; use it to mint a visitor token with read/write/end-chat scope; read transcript.
- **Automation:** headless browser harness that loads every widget iframe from a foreign origin, enumerates message handlers (`getEventListeners`), reports handlers whose source lacks `event.origin`/`event.source` checks, then fuzzes each command's fields with an HTML/JS canary.
- **Source:** [posts/mdp_sec/2026-11-25-2125441849108156479.md](../../posts/mdp_sec/2026-11-25-2125441849108156479.md).

## 3. Deprecated market still connected to shared liquidity (Kava Lend / HARD Lend, 53.9M KAVA)
- **Signal:** lending protocols with sunset assets (BUSD wind-down since 2023) whose market contracts remain deployed and share a pool with active assets.
- **Steps:** enumerate all markets/collateral assets/oracles from the controller (including paused/deprecated); review collateral valuation for each (decimals, price source, stale oracle, accounting of total collateral); model repeated borrow→liquidate loops for per-cycle gain; check whether liquidation incentives amplify inflated collateral.
- **Automation:** foundry fork test that iterates every listed market, mints/deposits the deprecated asset, borrows the shared-pool asset and liquidates in a loop, asserting pool balance deltas.
- **Source:** [posts/immunefi/2026-11-24-2125208065817653313.md](../../posts/immunefi/2026-11-24-2125208065817653313.md) (account is secondary, no PoC published).
