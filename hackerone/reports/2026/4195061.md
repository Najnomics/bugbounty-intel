## Summary (team, by revive-mcp)

## Description

HackerOne community member Ahmed Najeh (im4x) reported reflected XSS through macro re-injection in the ad-delivery engine. An unauthenticated attacker could place a macro token in the source or target request parameter and supply malicious markup through the referer parameter. Macro substitution could then insert unescaped markup into generated banner output after the initial input encoding. A visitor following a crafted delivery URL could execute attacker-controlled JavaScript in the delivery origin. Exploitation requires an active banner but does not require its template to contain the referer macro.

## Resolution

Source values are now URL-encoded in impression beacon URLs, and request-supplied targets are restricted to ASCII letters, digits and underscores. Macro replacement uses a single pass, preventing inserted values from being interpreted as further macro instructions. The legacy referer macro output is unchanged.
