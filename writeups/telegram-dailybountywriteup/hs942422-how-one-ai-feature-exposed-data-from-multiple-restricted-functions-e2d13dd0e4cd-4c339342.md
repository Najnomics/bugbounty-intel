Here we go again with another Broken Access Control story, and this time, there’s an interesting idea I wanted to shine some light on.

Let’s say we have a program called \`RandomService.com\`.

It’s a company that provides services for e-commerce store owners. As a store owner, you can sign up on \`RandomService.com\` and connect your store to get access to a complete set of services, including business analytics, data organization, customer support, and more.

The Support Agent role is mainly limited to features that help support staff do their job, such as responding to customers and resolving their issues.

Because of that, this role is restricted from accessing several features, including:

One of the AI features restricted to Support Agents is the **Artifacts** function.

In simple terms, an Artifact is the output generated by an AI Agent after completing a specific task.

For example, an admin might create an Artifact to collect the company’s financial activity over a certain period, or generate a summary of the company’s latest marketing campaigns.

I found an access control issue in the Artifacts function that allows a restricted member to retrieve all Artifacts that the admin has made publicly accessible to users who are allowed to access this feature.

This can be done through:

GET api/artifacts

The response reveals the ID of each Artifact.

The member can then take any of those IDs and use the following endpoint:

GET api/artifacts/ID

This returns the full contents of the selected Artifact, which may include sensitive information that the restricted member is not supposed to access.
