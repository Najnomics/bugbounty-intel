**Root-cause chain (from the linked Cursor + Fireworks bulletins, saved in full):** An attacker got a Cursor-issued access key that Fireworks exposed; used it to copy a read-only bucket of coding-agent traces (mostly 2025, non-Privacy-Mode) that Cursor could use for training; <0.01% of those traces held UN-REDACTED customer credentials; attacker pivoted via those creds into Cursor SaaS tools, archived non-prod source repos, support data, and a stored credential that let them push a malicious copy of Anthropic's Claude Code extension onto the CDN cache serving the Cursor VS Code extension marketplace (~5,000 users, ~11h window; Open VSX never had the malware).
**Harness takeaways (detection signals to encode):** (1) Hunt UN-REDACTED secrets in agent/LLM TRACE and training-data stores - `Authorization`, `Bearer`, `x-api-key`, AWS keys inside logged prompts/responses; trace redaction is a frequent gap. (2) Vendor/partner access keys exposed by a THIRD party are a top initial-access vector - map every outbound key you issue to a partner and scope it to its intended network. (3) Extension/plugin marketplace CDN caches can be poisoned with a stolen publish credential even when the upstream source is clean - verify served artifact hashes against the signed source, not just the marketplace listing. (4) Post-foothold movement is now LLM-fast: assume-compromise, isolate, monitor.
