## Analysis

**Keyword tags (automatic, from the post text):** XSS

**Full writeup saved:** [PortSwigger Research — "Achieving the impossible: XSS in innerHTML without equals" (guest post by Masato Kinugawa, 18 Nov 2026)](../../writeups/garethheyes/portswigger-xss-innerhtml-without-equals.md).
**Bug class:** DOM XSS / sanitizer & filter bypass via a new HTML element. The `<selectedcontent>` element (customizable `<select>`) clones the child nodes of the selected `<option>`; Chrome and Safari *execute cloned `<script>` elements*. That breaks the old rule that `<script>` inserted via `innerHTML` never runs, and needs no `=` (no attributes / event handlers).
**Payload (works in Safari 27.2; Chrome fixed behaviour in Chrome 153):**
```
document.body.innerHTML=`<select><selectedcontent></selectedcontent><option><svg><script>alert(1)<\/script>`
```
Related earlier finding: DOMPurify bypass GHSA-87xg-pxx2-7hvx (Kabir Acharya) using the same `<selectedcontent>` deferred-mutation trick.
**Harness checks:** (1) add `<select><selectedcontent></selectedcontent><option><svg><script>…` variants to the XSS payload set used when the reflection sink is `innerHTML`/`insertAdjacentHTML` and the filter blocks `=` or event-handler attributes; (2) run DOM-XSS verification in both Chromium <153 and WebKit (Safari) — a Chromium-only headless verifier will miss this; (3) for sanitizer targets, test whether the allowlist permits `select`, `selectedcontent`, `option`, `svg` and whether sanitizer output is re-parsed (mXSS). Bug class index: XSS → filter bypass (no `=`).
