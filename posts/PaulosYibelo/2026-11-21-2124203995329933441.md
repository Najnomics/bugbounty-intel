## Analysis

**Keyword tags (automatic, from the post text):** AI-assisted hunting

**Bug class:** Ghostscript Type 1 font-loader use-after-free (CVE-2026-125396 / Upload2Shell) reached remotely via ImageMagick/Pillow/Imagick/libvips/Qt EPS plugins and CUPS. Severity CVSS 4.0 8.5 (local AV in CVE); remote chains demonstrated for Roundcube (email thumbnail), WordPress+plugins (PDF/image upload), Debian 13 CUPS (anonymous IPP Print-Job).
**Root cause:** `.putgstringcopy` in `gs_fonts.ps` uses `.forceput` without type checks; a Type1 font can trap `typecheck` during `copy`, resume into `.forceput` with attacker-chosen (dict,key,value), plant a global→local dangling ref, then after `restore` overwrite native `ref`s (incl. `path_control_active`) and disable `-dSAFER` path control → `%pipe%` RCE.
**Detection / how to automate (in-scope):**
1. Inventory every upload/preview/thumbnail/print path that eventually calls ImageMagick, Imagick, Pillow `load()/crop()`, imageio, libvips `magickload`, Qt EPS plugin, or CUPS `gstopdf`.
2. Check installed Ghostscript version; anything < 10.08.0 is vulnerable (Ubuntu USN-8949-1, Debian tracker still lists Bookworm vulnerable as of 12 Nov).
3. Probe: upload EPS/PostScript bytes under a trusted extension (`.jpg`/`.png`/`.pdf`) that triggers a *pixel decode / preview / crop*; watch for `gs` spawn.
4. For CUPS: anonymous IPP Print-Job to shared queues that accept PostScript.
5. Harness check-spec: `upload_triggers_ghostscript` + `ghostscript_version < 10.08.0` → escalate; also flag Forminator/Essential Addons public upload fields that land in WP Media Library.
