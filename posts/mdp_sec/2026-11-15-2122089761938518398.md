## Analysis

**Bug class:** Broken access control — UI/page-level auth only; anonymous file-lookup API leaks direct storage URLs → unauthenticated download of confidential files (firmware, board designs).
**Root cause (from the post):** Gated pages redirected to sign-in, but the portal's own file API (an anonymous "file lookup") still returned the exact storage URL for each file; the storage URL was served without auth (public/unsigned object or long-lived signed link).
**Harness check:**
1. Crawl the authenticated portal once (or JS bundles) to collect API routes for files/attachments/downloads.
2. Replay every file/attachment metadata endpoint *logged out* (strip cookies + Authorization). Flag any JSON containing `url`, `downloadUrl`, `signedUrl`, `s3.amazonaws.com`, `blob.core.windows.net`, `storage.googleapis.com`.
3. Request the returned URL with no credentials; assert 403. Check signed-URL expiry (`X-Amz-Expires`, `se=`) > minutes.
4. Enumerate file IDs (sequential/guessable) for scale.
**Takeaway:** "Pages locked, data endpoints open" — test the API, not the page.
