## Analysis

**Bug class:** Hardcoded cryptographic key in a mobile app → decryption of a remote config blob that contained a **production private key**.
**Root cause (from the post):** Key was embedded in the client binary; it decrypted a config blob fetched on startup; that blob contained a production private key that should never have left a server. Same key ships to every install, so rotation of the client key alone changes nothing while the blob still encrypts under it.
**Harness check:**
1. Unpack APK/IPA; strings + jadx/ghidra for AES/RSA keys, keystores, `.pem`, base64 blobs next to "config"/"decrypt"/"bootstrap".
2. Intercept startup traffic; identify encrypted config downloads; try decrypting with keys found in the binary.
3. Assert decrypted material never contains server private keys, API master secrets, or long-lived tokens.
4. Automate: mobile-secret scanner → match against decrypted network blobs.
**Takeaway:** Client-side "encryption" of remote config is obfuscation. Anything the app can decrypt, the attacker with the APK can decrypt — never put production private keys in that blob.
