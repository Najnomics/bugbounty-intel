## Analysis

**Bug class:** Unauthenticated data-query API on a public data server → mass exfiltration of proprietary records (reported; closed as **duplicate, 135 days late** — the original was never fixed).
**Root cause (from the post):** Admin and token pages were locked down; the data query endpoints were not. Logged-out query returned real records with "no token, no cookie, nothing"; pagination allowed walking to the last record and reconstructing the whole dataset (millions of rows).
**Harness check:**
1. For any data platform (GraphQL/REST/OData/Elasticsearch/Solr/ArcGIS/Socrata-style servers) list query endpoints and call them without credentials.
2. If records return, test pagination params (`offset`, `page`, `cursor`, `$skip`, `from/size`, `resultOffset`) to the end; count total; stop at proof (row count + 2–3 redacted rows).
3. Distinguish intended-public datasets from proprietary ones (check ToS/data labels).
**Takeaways:** Duplicates of unfixed issues are common for "open data endpoint" bugs — check program response-time stats before investing; frame impact with total record count.
