## Analysis

**Keyword tags (automatic, from the post text):** RCE

**Bug class:** PostgreSQL type-confusion → reliable memory corruption / RCE (CVE-2026-6460 via pg_clickhouse; also a 22-year core primitive). Writeup by @mdisec (Mehmet İnce). Full text: [`writeups/0xacb/mdisec-pg-clickhouse-type-confusion-rce-cve-2026-6460.md`](../../writeups/0xacb/mdisec-pg-clickhouse-type-confusion-rce-cve-2026-6460.md).
**Root cause / method (from the writeup):** (1) pg_clickhouse Array→Datum conversion bug → OOB R/W (fixed 2026-06-23). (2) Core primitive: `CREATE TYPE … AS (key uuid); PREPARE … SELECT '(…uuid…)'::type; ALTER TYPE … ALTER ATTRIBUTE key TYPE bytea CASCADE; EXECUTE` — prepared composite bytes are not rewritten when the attribute type changes, so `record_out` → `byteaout` detoasts attacker-controlled UUID bytes as a fake ExpandedObjectHeader. Forge methods table → call `system()`; same primitive with 3 UUIDs forging an array leaks pointers via `unnest` type-confusion (text→bigint). Triggers as lowest-privilege login role.
**Detection / automation:** on any managed Postgres / extension-heavy instance: (a) fuzz `CREATE TYPE`/`ALTER TYPE … ALTER ATTRIBUTE` against prepared statements; (b) hunt extensions that rebuild Datums from foreign arrays (ClickHouse, etc.); (c) check whether `LANGUAGE internal` / composite ALTER is reachable from non-superuser.
