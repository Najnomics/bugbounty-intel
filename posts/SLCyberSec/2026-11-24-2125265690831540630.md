## Analysis

**Keyword tags (automatic, from the post text):** RCE

**Bug class:** Availability-limit → fail-open trust state → pre-auth RCE (Drupal core, SA-CORE-2026-017; duplicate of ANT-2026-GMRPK0BU found by Anthropic OSS Scanner).
**Detection signal:** an application `catch`es a resource error (EMFILE, DB `SQLSTATE[HY000] [1040] Too many connections`, `[2002] Cannot assign requested address` from TIME_WAIT source-port exhaustion) and falls back to a default/"not installed"/default-config state. Look for installers (`install.php`, first-admin routes in WordPress/Strapi/Drupal), `try{DB check}catch{$installed=false}`, config-file fallbacks to `requires_auth:false`.
**Exact method:** concurrent requests to a cheap endpoint (e.g. /core/authorize.php) until the DB connection limit is hit (Apache+PostgreSQL easiest: 100 slots < Apache workers; Apache+MySQL needs endpoints opening 2 connections; PHP-FPM needs Linux TIME_WAIT exhaustion: 28,232 ephemeral ports / 60s ≈ 471 new DB connections/s). Drupal installer sequence FAIL, FAIL, SUCCESS (verify DB → tableExists swallowed → requirements check) restarts the installer on a live site; choose SQLite with a database path inside the webroot and PHP code in the DB file → PHP execution. Affects Drupal 8.9/9/10/11, not 7. Benchmarks: ≥4 vCPU realistic remotely.
**How to automate:** (1) crawl for installer endpoints returning "already installed" vs "start installation"; (2) race harness (HTTP/2 multiplexing, N concurrent streams) hammering a connection-hungry endpoint while polling the installer; (3) check `tcp_max_tw_buckets`/FD limits for feasibility; (4) detection of any `catch(\Exception){}` that sets a permissive default.
