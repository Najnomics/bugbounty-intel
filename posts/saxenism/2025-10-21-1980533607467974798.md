> Yes. For that, we really need to drill down into constant-time coding practices.
> 
> What that means is implementing cryptographic code so that execution time, memory access and control flow DO NOT depend on secret data.
> 
> Eg,
> + No branching like `if(keybit == 1) { ... } else { ... }
> + No array lookups indexed by secret values
> + All operations (multiplication, XOR, modular exponentiation, etc) take identical time and touch identical memory addresses for all possible secrets.
> 
> All this would typically imply giving up on a few optimisation tricks, but it's all about how much hindrance you can add in the path of a really motivated adversary.
