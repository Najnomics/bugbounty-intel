> I've been pretty deep in TEE security research lately, and I came across this really fascinating style of hardware attack called "rowhammering".
> 
> Rowhammering, at the very basic level, means that you "hammer" a DRAM row so fast that it causes bit flips in adjacent rows. It's like playing cricket in your backyard, but being able to break the neighbour's window.
> 
> The DRAM is essentially an array of cells, and cells are basically a combo of capacitor + transistor. So, when you "read" a cell, a "row" is activated (the charge moves from the capacitor to the sense amplifier) and then the row is restored to baseline.
> 
> When you keep activating one "aggressor" row at high frequency, the electric fields leak and the neighbouring "victim" rows lose/gain charge. After enough cycles, bits in those rows flip.
> 
> Now you can argue that it would be difficult to find which physical rows correspond to which virtual address, finding "hammerable" addresses that sit next to sensitive rows, being able to access them bypassing caches, etc etc... but... there have been several successful attacks of this nature already.
> 
> For example, I was reading a paper (SGX-Bomb) where they were able to demonstrate that software inside an enclave could force the CPU into a locked state by hammering its own EPC page.
> 
> It’s insane that I can write software that abuses access patterns in silicon, which then abuses electric fields to flip bits in memory I should never be able to touch.
>
